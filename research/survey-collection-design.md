const popMean = stat?.mean, popStddev = stat?.stddev
top_percent = (1 - normalCDF(popMean, popStddev, userMean)) * 100

   이건 표본이 작은 문제가 아니라 **모집단이 가짜인** 문제다.

### 🔴 진단 2. 추천 정확도를 **한 번도 측정한 적이 없다**

2026-09-28 ~ 10-05 에 추천의 구조적 결함 네 가지를 고쳤다
(척도 불일치 / 반올림 동점 / 공유그룹 독식 / t2 상위5개 제한).
전부 **도달가능성**(무작위 사용자 프로파일 공간을 훑어 "이 직업이 TOP-N 에 들 수 있는가")
으로 검증했다. 응답 표본이 없어서 그 방법밖에 없었다.

⚠️ **도달가능성은 "구조적 배제가 없다"만 보장한다. 정확도가 아니다.**
   "추천이 맞는가" 는 여전히 **미지**다.

## 1. 두 모집단은 역할이 다르다

이 구분이 설계의 축이다. **같은 설문을 받지만 쓰임이 전혀 다르다.**

| | **실무자** (현직) | **예비 사용자** (학생·구직자) |
|---|---|---|
| 역할 | **정답지** | **분포 기준** |
| 무엇을 주는가 | "이 직업을 하는 사람은 이런 특성이다" | "우리 사용자는 이런 분포다" |
| 쓰이는 곳 | 추천 정확도 측정 · 직업 프로파일 · 가중치 최적화 · 매핑 검증 | **백분위 환산**(상위 N%) · 정규화 기준 |
| 핵심 변수 | **현재 직업** | 연령대 (규준 집단) |
| 표본 단위 | **직업군당** n명 | **전체** n명 |

⚠️ **둘을 섞어 통계를 내면 안 된다.** 실무자는 특정 직업에 편중된 표본이라
   그걸로 백분위를 만들면 "상위 N%" 가 왜곡된다.
   예비 사용자는 ground truth 가 없어 정확도 측정에 쓸 수 없다.
   → 저장도 분리한다(`survey_results_research` + `respondent.role` 구분).

## 2. 이 데이터로 무엇을 할 수 있게 되는가

### ① 추천 정확도 — **Recall@K** (가장 중요)

> 실무자의 검사 결과를 추천에 넣으면, **그 사람의 실제 직업**이 상위에 나오는가?

```
Recall@K = (자기 직업이 TOP-K 에 든 실무자 수) / (전체 실무자 수)
MRR      = 평균(1 / 자기 직업의 순위)
```

**이것이 추천의 유일한 직접 평가지표다.** 현재는 측정 불가.
공유 그룹(전문의 13종 등)은 **그룹 단위로 판정**한다 — 데이터가 동일해 개별 구분이 불가능하다.

⚠️ 기대치를 현실적으로 잡을 것. 537개(실질 481 독립 단위) 중 TOP5 는
   무작위면 1% 다. Recall@5 가 15~20% 만 나와도 무작위의 15~20배다.
   **첫 측정의 목적은 절대 수준이 아니라 기준선(baseline)을 박는 것**이다.

### ② 직업별 특성 프로파일을 우리가 직접 만든다

현재 직업 속성은 전부 고용24 출처다. 실무자 응답이 모이면
**"실제 종사자의 검사 특성 분포"** 라는 독립된 데이터가 생긴다.

- 고용24 데이터와 **대조** → 어긋나는 직업을 찾아낸다
- 고용24에 없는 축(T3 업무환경 선호 등)을 메운다
- 통합 조사된 85직업(29그룹)을 **우리 데이터로 분리**할 수 있다
  ← 전문의 13종이 점수가 똑같아 한 자리로 접어야 했던 문제의 근본 해결

### ③ 가중치 최적화

Recall@K(또는 MRR)를 목적함수로 5축 가중치를 탐색한다.
⚠️ **반드시 학습/검증 분리**(train/test split). 같은 표본으로 맞추고 같은 표본으로
   자랑하면 과적합을 성능으로 오해한다.

### ④ 매핑표 검증

실무자 데이터로 **상관**을 본다: "T1 의 E(외향) 점수가 높은 사람이 실제로
`PS` 외향 속성이 높은 직업에 종사하는가?"
상관이 0 이거나 **부호가 반대면 그 매핑은 틀렸다.** 지금은 확인할 길이 없다.

### ⑤ 백분위 환산 기준 교체 (즉시 효과)

더미 92건 기반 `group_stats` → **예비 사용자 실제 분포**로 교체.
사용자가 보는 "상위 N%" 가 처음으로 의미를 갖는다.
**네 가지 중 가장 먼저 효과가 나고, 가장 적은 표본으로 된다.**

## 3. 수집 범위 — 몇 명이 필요한가

### 산출 근거

**(a) 직업군 프로파일 추정** — 0~1 척도 특성의 평균을 오차 ±m 로 추정
```
n = (1.96 · σ / m)²        σ = 직업군 내 표준편차
σ=0.20, m=0.10 → n ≈ 16     σ=0.20, m=0.07 → n ≈ 32
σ=0.25, m=0.10 → n ≈ 24     σ=0.25, m=0.07 → n ≈ 49
```
⚠️ **σ 는 아직 모른다.** 위 값은 0~1 정규화 특성의 통상 범위를 가정한 것이다.
   **파일럿에서 실측한 σ 로 이 표를 다시 계산해야 한다.**

**(b) 비율 추정** (Recall@K)
```
n = 1.96² · p(1-p) / m²    (p=0.5 최악 가정)
m=±10%p → n ≈ 96          m=±5%p → n ≈ 384
```

**(c) 두 직업군의 차이 검출** (effect size d=0.5, power 0.8) → **군당 64명**

**(d) 규준(norm) 집단** — 백분위표를 만들려면 분포 전체가 필요하다.
심리검사 규준 관행은 규준집단당 **300명 이상**.

### ⚠️ 먼저 — 완주 100% 만 반영한다 (2026-10-05 결정)

**부분 응답은 분석에 쓰지 않는다.** 이 결정이 모집 비용을 직접 좌우한다:

```
필요 모집 인원 = 목표 유효 응답 ÷ 완주율
```

103문항 · 모바일 · 무보상 설문의 완주율은 통상 **40~70%** 다.
중간 저장과 진행률 표시가 있으면 상단, 없으면 하단이다.

| 완주율 가정 | 유효 100명 | 유효 200명 | 유효 300명 |
|---|---|---|---|
| 50% | 200명 시작 | 400명 | 600명 |
| **60%** (중간저장 有) | **167명** | **334명** | **500명** |
| 75% (최선) | 134명 | 267명 | 400명 |

⚠️ **완주율은 가정이다. Phase 1 에서 실측해 이 표를 다시 계산할 것.**
⚠️ 그래서 **중간 저장·진행률·파트 분할이 '편의 기능' 이 아니라 비용 절감 수단**이다.
   완주율 50% → 70% 는 모집 인원을 **29% 줄인다.**

### 권고 — 3단계

#### 📊 티어별 목표 (유효 응답 기준)

| | **실무자** | **예비 사용자** | 얻는 것 |
|---|---|---|---|
| **검증 하한** | **50명** | 100명 | "근본적으로 틀렸는지"만. Recall@K ±14%p — **기준선으로 쓰기엔 거칠다** |
| **🔴 최소선** | **100명** | **200명** | Recall@K **±10%p** → 알고리즘 변경 효과를 판정할 수 있다 · 백분위 교체(5%p 단위) |
| **🟢 권장** | **200명** | **300명** | + **σ 실측** · 대분류별 방향 판단 · 규준 관행(300) 충족 |
| **🔵 이상** | **400명** | **500명** | Recall **±5%p** · 가중치 최적화(train/test 분리) · 연령대별 규준 분리 |

#### 실무자 — 티어별 구성 조건

**검증 하한 (50명)** — 모이는 대로. 대분류 제약 없음.
> 쓸 수 있는 것: Recall@30 이 0% 에 가까운가 같은 **극단 판정**뿐.
> 이 구간에서는 "개선됐다" 는 말을 **하지 말 것** — 오차가 변화량보다 크다.

**🔴 최소선 (100명)** — 쏠림 제약이 필요하다.
```
· 대분류 5개 이상 포함
· 한 대분류가 전체의 40% 초과 금지
```
> 제약이 없으면 100명이 한 직업군에서 나와 Recall@K 가 그 군에만 맞춰진다.
> 가중치를 그 표본으로 조정하면 **다른 직업군 사용자에게 더 나빠진다.**

**🟢 권장 (200명)** — 대분류 10개 × 각 20명.
> 20명이면 직업군 평균 오차 ±0.10(σ=0.20 가정). **방향 판단용이고 프로파일 확정은 아니다.**
> 여기서 σ 를 실측해야 Phase 2 인원이 정해진다.

**🔵 이상 (400명)** — 권장 200 + 핵심 직업군 쏠림 허용.
> train 250 / test 150 으로 나눠 가중치 최적화를 **검증까지** 할 수 있다.

#### 예비 사용자 — 티어별 의미

| 인원 | 백분위표 신뢰 구간 |
|---|---|
| 100명 | **10%p 단위**까지만. "상위 23%" 같은 표기는 과장이다 |
| **200명 (최소선)** | 5%p 단위. 더미 92건보다 분명히 낫다 |
| **300명 (권장)** | 심리검사 규준 관행 하한 충족 |
| 500명 (이상) | 연령대별(10대/20대/30대+) 분리 규준 검토 가능 |

⚠️ **연령대별 규준을 나누려면 각 연령대가 위 인원을 따로 채워야 한다.**
   전체 300명을 3개 연령대로 쪼개면 각 100명 = 10%p 단위로 떨어진다.
   Phase 1·2 는 **단일 규준**으로 가고, 분리는 500명 이후에 판단한다.

#### Phase 2 — 핵심 직업군

대분류는 너무 거칠다(연구직 112개 직업을 한 묶음으로 볼 수 없다).
**핵심 직업군 20~30개 × 군당 30명 = 600~900명.**

선정 기준:
1. 현재 추천에서 **실제로 상위에 나오는** 직업군 (= 사용자가 보게 되는 것)
2. 모집이 **현실적인** 직업군
3. 고용24 데이터가 **통합 조사된** 29그룹 — 우리 데이터로 분리할 가치가 가장 크다
4. 대분류 커버리지 유지 (쏠리면 가중치 최적화가 편향된다)

⚠️ **군당 인원은 Phase 1 의 σ 실측 후 확정한다.** 30명은 σ=0.20 가정값이다.

#### Phase 3 — 지속 수집

본서비스 가입자에게 **동의받아** 편입(별도 컬렉션 유지). 분기별 규준 재계산.

> 💡 **모집이 어려우면 티어를 낮추지 말고 범위를 좁혀라.**
> 대분류 10개 × 20명(200) 보다 **대분류 5개 × 20명(100)** 이 낫다 —
> 전자를 반만 채우면 모든 분석이 애매해지지만, 후자는 그 5개에 대해 **확실한 결론**이 나온다.
> 커버리지는 Phase 2 에서 넓히면 된다.

## 4. 수집할 데이터 항목

### 4.1 확정 (사용자 결정)

| 항목 | 형식 | 왜 필요한가 |
|---|---|---|
| **신분** | 사용자 / 실무자 | 두 모집단 분리의 전제 |
| **현재 직업** | 537개 중 선택 | **정답지의 핵심.** 없으면 ①②③④ 전부 불가 |
| **경력 연수** | 1년미만/1~3/3~5/5~10/10년+ | 응답 신뢰도 가중치 |
| **연령대** | 10대/20대/.../60대+ | 규준 집단 분리 |
| **성별** | 남/여/선택안함 | 분포 파악 |

### 4.2 확정 (2026-10-05 결정) — 적합감 · 응답 품질

#### ✅ ① 직무 적합감 (1~5)

> "지금 하는 일이 자신에게 맞다고 느끼십니까?"

**실무자 중에도 '안 맞는데 하는 사람'이 있다.** 그 응답을 그대로 정답지로 쓰면
**정답지가 오염된다** — "이 직업 종사자의 특성" 이 아니라 "이 직업에 흘러온 사람의 특성"
이 되어, 추천이 '적성'이 아니라 '현실의 쏠림'을 학습한다.

쓰임:
- 가중치: 적합감 높은 응답에 비중을 더 준다
- 민감도 분석: 적합감 4~5 만으로 Recall@K 를 다시 재서 비교한다
- ⚠️ 적합감으로 **걸러내지는 말 것**(표본이 줄고 선택 편향이 생긴다). **가중치로** 쓴다

#### ✅ ② 응답 품질 지표

103문항 공개 설문이면 **불성실 응답이 반드시 섞인다.** 목적이 '신뢰성 확보'인데
불성실 응답을 걸러낼 수단이 없으면 목적 자체가 무너진다.

| 지표 | 방법 | 판정 |
|---|---|---|
| 총 소요시간 | 시작·제출 타임스탬프 | 103문항을 **3분 미만**에 끝내면 의심 |
| 직선 응답(straight-lining) | 동일 선택지 연속 길이 | **20문항 이상 연속 동일** → 의심 |
| 미완료율 | 파트별 이탈 지점 | 설문 길이 조정 근거 |

⚠️ **삭제하지 말고 플래그만 단다**(`quality.suspect`). 분석 때 포함/제외를 비교해
   결론이 뒤집히는지 본다. 지우면 되돌릴 수 없다.

⚠️ 중복 제출은 공개 URL 에서 **완전 차단이 불가능**하다. 핑거프린팅은 과하다.
   제출 토큰 + 소요시간 + 레이트리밋으로 **줄이고**, 남은 중복은 통계적으로 감당한다.

### 4.3 확정 (2026-10-05 결정) — 예비 사용자의 희망 직업

| 항목 | 형식 | 쓰임 |
|---|---|---|
| **희망 직업** | 537개 중 선택 (복수 허용 검토) | 「희망 직업이 추천 상위에 나오는가」 보조 지표 |

🚨 **ground truth 가 아니다. 실무자 Recall 과 같은 지표로 취급하지 말 것.**
희망은 **정보 부족·편견·유행**을 포함한다. 중학생이 '유튜버' 를 적는 것은
적성의 증거가 아니다. 실무자 Recall 과 섞어 평균을 내면 지표가 오염된다.

올바른 쓰임 세 가지:
1. **별도 지표로 보고**한다 — `Recall@K(실무자)` 와 `Hit@K(희망)` 을 **따로** 적는다
2. **괴리 분석** — 희망 직업과 추천 결과가 체계적으로 어긋나는 지점을 찾는다.
   그게 "사용자가 모르는 적합 직업" 일 수도, **우리 추천의 결함**일 수도 있다
3. **수요 파악** — 희망이 쏠리는 직업군은 진로백과 콘텐츠 보강 우선순위가 된다

⚠️ 희망 직업을 **가중치 최적화의 목적함수에 넣지 말 것.** 넣으면 추천이
   '적합한 직업' 대신 **'사람들이 이미 원하는 직업'** 을 학습한다 — 추천의 존재 이유가 사라진다.

### 4.4 받지 않을 것

이름·연락처·학교·회사명 — **수집 목적에 불필요하다.**
개인정보처리방침(`/privacy`)에 수집 항목을 명시했고, 목적 외 수집은 그와 어긋난다.
`respondent_id` 는 **서버 생성 난수**로 둔다(재식별 불가).

## 5. 분석 설계 — 모으고 나서 무엇을 어떻게 보는가

### 5.1 즉시 (Phase 1 직후)

1. **σ 실측** → 3장 표본 산출표를 실제 값으로 다시 계산. **Phase 2 인원이 여기서 확정된다**
2. **백분위 기준 교체** — 예비 사용자 분포로 `group_stats` 재생성
   ⚠️ 기존 `survey_statistics` 를 덮어쓰지 말고 **새 문서로** 쓴다. 되돌릴 수 있어야 한다
3. **Recall@K 기준선** — 현재 알고리즘으로 측정해 **숫자를 박아둔다.**
   이후 모든 변경은 이 수치와 비교한다

### 5.2 Phase 2 이후

4. **매핑표 상관 분석** — 축별로 사용자 특성 ↔ 종사 직업 속성. 부호 반대·무상관 매핑 색출
5. **가중치 최적화** — 목적함수 Recall@5 또는 MRR, train/test 분리, 좌표하강 또는 그리드
6. **고용24 데이터 대조** — 우리 실무자 프로파일 vs 고용24 직업 속성. 괴리 큰 직업 목록화
7. **공유 그룹 분리 검토** — 29그룹을 우리 데이터로 구분할 수 있는지

### 5.3 지표 정의를 먼저 고정할 것

⚠️ **분석을 시작하기 전에** Recall@K 의 K, 공유그룹 판정 규칙, 적합감 가중 방식을
   문서로 고정한다. 결과를 보고 지표를 고르면 **무엇을 하든 좋아 보이게** 만들 수 있다.
