> 크롤링·정리: 2026-09-26. **정식 API 등록 완료 상태.**
>
> ⚠️ 원문 페이지는 명세를 AJAX(`selectOpenApiSvcInfoPost.do`)로 불러오고, 세 API가
> **한 페이지의 탭 3개**로 되어 있다. curl 로는 본문이 안 잡히므로 브라우저 렌더링이 필요하다.

## 공통

| 항목 | 값 |
|---|---|
| 호스트 | `https://www.work24.go.kr` (명세 페이지는 `m.work24.go.kr`, **호출은 `www`**) |
| 인증 | 쿼리스트링 `authKey` |
| 응답 형식 | `returnType=XML` — **3종 모두 XML 고정** |

> ⚠️ `returnType` 에 JSON 을 지정하는 선택지가 명세에 없다. 3종 모두 "XML 을 반드시 지정" 이다

> 기존 API 응답 규약이 `{success, data, error}` JSON 이므로 **변환 계층이 필요하다.**

> ⚠️ 요청 Parameter 에 대괄호 `[]` 는 제외하고 넣는다(명세 주의문).

## 1. 직업정보 (목록/검색)

**요청 URL**
```
https://www.work24.go.kr/cm/openApi/call/wk/callOpenApiSvcInfo212L01.do
```

**안내**: 직업정보 키워드 검색, 조건별 검색, 분류별 카테고리 정보로 직업명을 검색할 수 있고,
직업상세에 대한 정보를 직업정보 API를 통해 이용할 수 있습니다.

**사용예제**
```
...callOpenApiSvcInfo212L01.do?authKey=[인증키]&returnType=XML&target=JOBCD
```

**요청 Parameters**

| 항목 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `authKey` | String | Y | 인증키 |
| `returnType` | String | Y | `XML` 고정 |
| `target` | String | Y | `JOBCD` 고정 |
| `srchType` | String | N | 검색타입(미입력 시 `K`). **단일 검색만 가능**<br>`K`: 키워드 검색 / `C`: 조건별 검색(연봉·전망) |
| `keyword` | String | N | `srchType=K` 일 때만. 직업명 키워드. UTF-8 인코딩 |
| `avgSal` | String | N | `srchType=C` 일 때만. 미입력 시 전체<br>`10` 3천만원 미만 / `20` 3~4천 / `30` 4~5천 / `40` 5천만원 이상 |
| `prospect` | String | N | `srchType=C` 일 때만. 미입력 시 전체<br>`1` 증가 / `2` 다소 증가 / `3` 유지 / `4` 다소 감소 / `5` 감소 |

> ⚠️ **페이지네이션 파라미터가 없다**(`startPage`/`display` 미제공). 직업사전(3번)에는 있다.
> 전체 목록을 받으면 몇 건이 오는지는 실호출로 확인해야 한다.

**출력결과 (XML)**
```xml
<jobsList>
  <total>Number 총건수</total>
  <jobList>
    <jobClcd>String 직업분류코드</jobClcd>

    <jobCd>String 직업코드</jobCd>
    <jobNm>String 직업명</jobNm>
  </jobList>
</jobsList>
```

```

```

```
...callOpenApiSvcInfo212D01.do?authKey=[인증키]&returnType=XML&target=JOBDTL&jobGb=1&jobCd=[직업코드]&dtlGb=[상세구분]
```

**요청 Parameters**

| 항목 | 타입 | 필수 | 설명 |

| `returnType` | String | Y | `XML` 고정 |

## 3. 직업사전

**요청 URL**
```
https://www.work24.go.kr/cm/openApi/call/wk/callOpenApiSvcInfo212L50.do
```

**안내**: 직업사전 API를 활용하여 한국고용정보원이 발간한 직업사전을 직접 구성할 수 있습니다.

**사용예제**
```
예제1) ...212L50.do?authKey=[인증키]&returnType=XML&target=dJobCD&startPage=1&display=10&srchType=K&keyword=[키워드]
예제2) ...212L50.do?authKey=[인증키]&returnType=XML&target=dJobCD&startPage=1&display=10&srchType=EL|WS|SY&eduLevel=[교육수준]&workStrong=[직업강도]&skillYear=[숙련기간]
```

**요청 Parameters**

| 항목 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `authKey` | String | Y | 인증키 |
| `returnType` | String | Y | `xml` 고정 |
| `startPage` | Number | Y | 기본 1, **최대 1000** |
| `display` | Number | Y | 출력건수. 기본 10, **최대 100** |
| `target` | String | Y | `dJobCD` 고정 |
| `srchType` | String | Y | 검색타입 (아래) |
| `keyword` | String | K일 때 필수 | 직업명 키워드. UTF-8. 유사·관련 직업 검색 가능 |
| `empJobCl` | String | E일 때 필수 | 한국고용직업분류 |
| `stdJobCl` | String | J일 때 필수 | 한국표준직업분류 |
| `stdIndCl` | String | I일 때 필수 | 한국표준산업분류 |
| `eduLevel` | String | EL일 때 필수 | `1` 6년 이하(초졸 이하) / `2` 6~9년(중졸) / `3` 9~12년(고졸) / `4` 12~14년(전문대졸) / `5` 14~16년(대졸) / `6` 16년 초과(대학원 이상) |
| `workStrong` | String | WS일 때 필수 | `SW` 아주 가벼운 / `LW` 가벼운 / `MW` 보통 / `HW` 힘든 / `VH` 아주 힘든 |
| `skillYear` | String | SY일 때 필수 | `1` 약간의 시범 / `2` 시범후 30일 이하 / `3` 1~3개월 / `4` 3~6개월 / `5` 6개월~1년 / `6` 1~2년 / `7` 2~4년 / `8` 4~10년 / `9` 10년 초과 |
| `workPlace` | String | WP일 때 필수 | `I` 실내 / `O` 실외 / `B` 실내·외 |
| `workFunc1` | String | F1일 때 필수 | 직무기능(자료) `0` 종합 / `1` 조정 / `2` 분석 / `3` 수집 / `4` 계산 / `5` 기록 / `6` 비교 |
| `workFunc2` | String | F2일 때 필수 | 직무기능(사람) `0` 자문 / `1` 협의 / `2` 교육 / `3` 감독 / `4` 오락제공 / `5` 설득 / `6` 말하기-신호 / `7` 서비스 제공 / `8` 관련없음 |
| `workFunc3` | String | F3일 때 필수 | 직무기능(사물) `0` 설치 / `1` 정밀작업 / `2` 제어조작 / `3` 조작운전 / `4` 수동조작 / `5` 유지 / `6` 투입-인출 / `7` 단순작업 / `8` 관련없음 |

**`srchType` 값**

| 단일 검색만 가능 | 다중 검색 가능 (`|` 로 결합, 예 `EL\|WS\|SY`) |
|---|---|
| `K` 키워드(keyword)<br>`E` 한국고용직업분류(empJobCl)<br>`J` 한국표준직업분류(stdJobCl)<br>`I` 한국표준산업분류(stdIndCl) | `EL` 교육수준 / `WS` 직업강도 / `SY` 숙련기간 / `WP` 작업장소<br>`F1`·`F2`·`F3` 직무기능(자료·사람·사물) |

> ⚠️ `K`/`E`/`J`/`I` 는 **단일만** 되고, `EL`/`WS`/`SY`/`WP`/`F1~F3` 만 `|` 로 묶을 수 있다.
> 섞어 쓰면 안 된다.

**출력결과 (XML)**
```xml
<dJobsList>
  <total>총건수</total>
  <startPage></startPage>
  <display></display>
  <dJobList>
    <dJobCd>직업사전 세세분류 코드</dJobCd>
    <dJobCdSeq>직업사전 세세분류 순번</dJobCdSeq>
    <dJobNm>세세분류 직업명</dJobNm>
  </dJobList>
</dJobsList>
```

> ⚠️ 직업사전은 **코드와 이름만** 돌려준다. 상세 본문을 주는 엔드포인트는 이 명세에 없다.
> 직업사전 본문이 필요하면 별도 API 를 더 찾아야 한다.

> 💡 **이 파일이 곧 직업사전 전량이다.** API #3 은 검색 API 이므로, 코드 목록이 필요할 뿐이라면
> API 를 호출하지 않고 이 파일을 쓰는 편이 빠르고 호출 한도도 아낀다.

## 🚨 직업사전 코드는 우리 jobCode 와 **다른 체계**다 (2026-09-26 실측)

| | 우리 `job_data.job_info` | 직업사전 |
|---|---|---|
| 분류 체계 | **한국고용직업분류(KECO)** — 경영·사무·금융·보험직 … | **한국표준직업분류(KSCO)** — 1 관리자 / 2 전문가 / … / 9 단순노무 / A 군인 |
| 코드 | **6자리** (`011102`) | **4자리 + 일련번호** (`1110`-`1`) |
| 건수 | 537 | 6,359 |

**코드 문자열 교집합 0건.** 자릿수부터 다르므로 코드로는 이을 수 없다.

이름으로 이어보려 해도 부족하다 (537건 전수 대조):

| 방식 | 건수 |
|---|---|
| 직업명 정확 일치 | 136 (25%) |
| 유사·관련 직업명까지 포함 | +74 (13%) |
| **불일치** | **327 (60%)** |

불일치의 대부분은 우리 직업명이 **묶음 단위**여서다 — "초등학교 교장 및 교감",
"영업기획·관리·지원사무원", "정보통신컨설턴트 및 감리원" 처럼 여러 직업을 한 항목으로 합쳐 놨는데
직업사전은 낱개로 쪼개져 있다.

> **결론: 직업사전을 우리 537건에 직접 붙이는 것은 불가능하다.** 별개 데이터셋으로 다루거나,
> 매핑 테이블을 사람이 만들어야 한다. 착수 전에 "직업사전으로 무엇을 하려는가"를 먼저 정할 것.

## ✅ 실호출 비교 결과 (2026-09-26, 인증키로 실측)

**목적**: 기존 "크롤링 → DB 적재 → 우리 API 로 재호출" 방식을 공식 API 로 **대체**할 수 있는가.

### 1) 공식 API 가 압도적으로 풍부하다

크롤링본은 **모든 항목이 예외 없이 상위 5개씩만** 들어 있다(표본 30건 전수 확인, 120/120·116/116…).
사이트가 5개만 보여줘서 그만큼만 긁힌 것이다. 공식 API 는 전량을 준다.

| 영역 | 크롤링본 | 공식 API | 배수 |
|---|---:|---:|---:|
| 업무수행능력 | 5 | **44** | 8.8× |
| 지식 | 5 | **33** | 6.6× |
| 업무환경 | 5 | **49** | 9.8× |
| 성격 | 5 | **16** | 3.2× |
| 업무활동 | 5 | **41** | 8.2× |
| 가치관 | 5 | 9 | 1.8× |
| 흥미 | 5 | 6 | 1.2× |

공식 API 만 주는 것도 있다:
- **항목 설명문**(`jobAblCont` 등) — "직원의 근로의욕을 높이고 능력을 개발하며 적재적소에 인재를 배치한다"
- **학력 분포**(dtlGb=3) — 대졸 47 / 석사 37 / 박사 17 (%)
- **전망 산문**(dtlGb=4), **되는길**(`way`), **관련직업**(`relJobList`)

### 2) 속성 마스터는 이미 우리가 전량 갖고 있다

`reference_data.career_attributes` 202건의 개수가 API 반환 개수와 **정확히 일치**한다.

|---|---:|---:|---|
| ability | 44 | 44 | **44/44** ✅ |
| knowledge | 33 | 33 | **33/33** ✅ |
| work_environment | 49 | 49 | **49/49** ✅ |
| personality | 16 | 16 | **16/16** ✅ |
| work_activity | 41 | 41 | **41/41** ✅ |
| interest | 6 | 6 | **6/6** ✅ |
| **value** | **13** | **9** | **2/9** 🚨 |

> 💡 즉 **크롤링 때 속성 마스터는 전부 가져왔고 직업별 점수만 5개씩 잘린 것**이다.
> API 는 코드를 안 주고 이름만 주지만(`jobAblNm`), 괄호·구분기호를 정규화하면
> 가치관을 뺀 191/191 이 우리 코드에 그대로 붙는다.
> (정규화 필요 예: `현실형(Realistic)`→`현실형`, `고장의 발견.수리`→`고장의발견수리`)

### 3) 🚨 걸림돌 4가지

**① 가치관 체계가 다르다 — 정의를 보면 대부분 리네이밍이다**

| | 항목 |
|---|---|
| 우리(13) | 성취·개인지향·다양성·지적 추구·경제적 보상·영향력·자율·애국·인정·이타·고용안정·심신의 안녕·신체활동 |
| API(9) | 성취·경제적 보상·변화지향·사회적 공헌·사회적 인정·일과 삶의 균형·자기개발·자율성·직업안정 |

이름만 보면 공통이 2개뿐이지만, **정의문을 대조하면 9개 중 9개가 우리 코드에 대응된다.**

| 공식 API (9) | 정의 | → 우리 | 판정 |
|---|---|---|---|
| 성취 | 자신이 세운 목표를 이루고 달성 | VA01 성취 | 동일 |
| 경제적 보상 | 일에 대한 정당한 대가로서의 돈 | VA05 경제적 보상 | 동일 |
| 자율성 | 자율적으로 업무를 해나가는 것 | VA07 자율 | 동일 |
| 사회적 인정 | 다른 사람에게 인정받는 것 | VA09 인정 | 동일 |
| 직업안정 | 오랫동안 안정적으로 일할 수 있는지 | VA11 고용안정 | 동일 |
| 사회적 공헌 | 다른 사람이나 사회에 도움이 되는 것 | VA10 이타 | 동일 |
| 변화지향 | 고정되어 있지 않고 변화 가능한 것 | VA03 다양성 | 동일 |
| 자기개발 | 지식·기술·능력을 발전시켜 성장 | VA04 지적 추구 | 근접 |
| 일과 삶의 균형 | 삶에서도 만족할 균형 | VA12 심신의 안녕 | 근접 |

**새 9개 체계에 대응이 없는 우리 코드 4개**: VA02 개인지향 / VA06 영향력 / VA08 애국 / VA13 신체활동.

### 왜 이 4개만 갈 곳이 없나 — 고용24가 '가치관'의 범위를 좁혔다

옛 13개 체계에는 **가치관이 아닌 것이 섞여 있었다.** 새 9개는 "일에서 무엇을 중시하는가"만
남기고, 업무 방식·신체 조건처럼 **다른 카테고리에서 이미 측정되는 것**을 뺐다.

| 우리 코드 | 정의 | 실제 성격 | 어디서 이미 측정되나 |
|---|---|---|---|
| VA02 개인지향 | 혼자 일할 수 있다 | 업무 **방식** 선호 | `WE05` 다른 사람과의 상호작용(팀으로 일하는 중요성), `WE04`·`WE06` 접촉 빈도 |
| VA13 신체활동 | 신체활동을 많이 하지 않아도 된다 | **신체 조건** | `WE02` 앉아서 근무, `WE38` 서서 근무, `WE41` 걷거나 뛰기, `WE13` 반복적 신체행동, `WE22` 균형 유지, `WE40` 몸 구부리기 — **9개 항목** |
| VA06 영향력 | 타인에 대해 영향력을 발휘 | 성격 + 재량 | `PS14` 리더십, `WE17` **이미지/평판/재정에 미치는 영향력**(이름이 거의 같다), `WE14` 의사결정 권한, `WE20` 의사결정 가능성 |
| VA08 애국 | 국가를 위해 도움이 될 수 있다 | 가치관이지만 **너무 좁음** | 새 체계의 **사회적 공헌**(다른 사람이나 사회에 도움)에 흡수. VA10 이타와 합쳐졌다 |

> 💡 VA08 은 우리도 같은 문제를 느꼈다. `surveyToCareerMapping.js` 가
> **"DEDICATION(헌신)은 VA08(애국)을 대체하는 의도적 리네이밍"** 이라고 적어둔 것과,
> 고용24가 '애국'을 '사회적 공헌'으로 바꾼 것은 **같은 문제의식**이다.

### 그래서 전환은 손실이 아니라 정밀화다

이 4개 개념은 전환 후 **더 정밀하게** 측정된다. 업무환경을 5개가 아니라 **49개 전량**으로 받기 때문이다.

| | 지금 | 전환 후 |
|---|---|---|
| '신체활동' | VA13 **1개**로 뭉뚱그림. 그나마 상위 5위 밖이면 **아예 없음** | WE 9개 항목으로 분해 측정 (49개 전량 수신) |
| '개인지향' | VA02 1개 | WE04·WE05·WE06 |
| '영향력' | VA06 1개 | PS14 + WE14·WE17·WE20 |

⚠️ 단 **추천 알고리즘은 자동으로 따라오지 않는다.** T23 4문항을 가치관 축이 아니라
WE/PS 축으로 옮겨 쓰려면 매칭 설계를 손대야 한다. 문항을 그대로 두고 그 4개만
매칭에서 빼는 것이 가장 작은 변경이다.

### 그런데 커버리지는 오히려 **늘어난다**

지금은 직업당 **가치관 상위 5개**만 크롤링돼 있다. 공식 API 는 그 직업의 **9개 전부**를 준다.

| | 우리 13개 코드 중 점수가 있는 것 |
|---|---|
| 현행(크롤링) | **5개** (상위 5만) |
| 공식 API 전환 후 | **9개** |

즉 "4개를 잃는다"가 아니라 **"5개 → 9개로 늘고, 그 4개는 영구히 빈다"** 가 정확하다.

### ⚠️ 다만 T23 검사가 이 13개에 맞춰 설계됐다

`config/surveyToCareerMapping.js` 주석:
> T23 설문은 job_data 의 value 카테고리와 **1:1 대응하도록 설계됨.**
> DEDICATION(헌신)은 VA08(애국)을 대체하는 **의도적 리네이밍**.

T23 13문항이 VA01~VA13 에 1:1로 묶여 있다(`config/matchingMaps.js` `T23_TO_VA`,
`recommendController.js` 에 **같은 표가 중복**으로 하드코딩돼 있으니 고칠 때 둘 다 볼 것).
**추천 점수에서 T23 비중은 20%** 다.

전환하면 T23 4문항(개인지향·영향력·헌신·신체활동)은 직업 쪽 대응값이 사라진다.
검사 문항을 그대로 둘지, 9개 체계에 맞춰 다시 설계할지는 **별도 판단이 필요하다.**

**② 직업 수가 오히려 줄어든다: 492 < 537**

API `total=492`, 우리 537건. **45건 적다.** 이름 일치 352/537(65%)인데, 불일치는 대부분
표기 차이다(`보건·의료관리자` ↔ `보건 의료 관련 관리자`, `여행·호텔관리자` ↔ `여행·숙박(호텔)관리자`).
정규화하면 올라가겠지만 **우리에만 있는 직업이 남는 것은 확실하다.**

**③ 직업코드가 완전히 다르다**

API `jobCd` = **`K000000933`** (K + 9자리). 우리 `jobCode` = **`011102`** (6자리 KECO).
`jobClcd` 도 3자리(`011`)로 우리 분류와 다르다. **코드 전면 교체 + 매핑 테이블이 필요하다.**
북마크·추천직업·목표진로가 전부 `jobCode` 문자열을 들고 있어 **기존 사용자 데이터 마이그레이션**이 딸려온다.

**④ 호출량**

상세는 `dtlGb` 7개를 각각 불러야 한다 → **492 × 7 = 3,444 호출**로 1회 전량 수집.
실시간 프록시로 쓰면 직업 상세 1건 볼 때마다 최대 7회다. **적재 후 서빙(현행 구조 유지)이 현실적.**

### 4) 실측에 쓴 호출

```
목록  callOpenApiSvcInfo212L01.do?authKey=..&returnType=XML&target=JOBCD              → total 492
상세  callOpenApiSvcInfo212D01.do?authKey=..&returnType=XML&target=JOBDTL&jobGb=1
        &jobCd=K000000933&dtlGb=1..7                                                  → 7개 섹션 모두 200
```

> dtlGb 별 응답 루트 태그: 1 `<jobSum>` / 2 `<jobsDo>` / 3 `<way>` / 4 `<salProspect>`
> / 5 `<ablKnwEnv>` / 6 `<chrIntrVals>` / 7 `<jobActv>`
> 반복 항목은 `Cmpr` 접미사가 **직업내(5점 척도)**, 없으면 **직업간(100점 백분위)** 이다.
> 우리 `details.<영역>.<중요도|수준>.<직업내|직업간>` 구조와 그대로 대응한다.
