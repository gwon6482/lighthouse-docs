| 엔드포인트 | 역할 |
|---|---|
| `GET /api/auth/providers` | FE 가 버튼을 켤지 묻는다. **플래그의 유일한 진실은 API env** |
| `GET /api/auth/kakao` | state(서명된 10분 JWT) 붙여 카카오 인가 페이지로 302 |
| `GET /api/auth/kakao/callback` | 코드→토큰→프로필→계정→우리 JWT 발급 후 FE 로 302 |

설계는 9/9 작업 그대로다 — 토큰은 쿼리가 아닌 **프래그먼트(`#token=`)**(CloudFront 로그·Referer 에
안 남는다), 신원은 **카카오 회원번호**로만 판단(이메일은 바뀔 수 있어 표시용 스냅샷), 같은 이메일
로컬 계정이 있어도 **자동 연결하지 않는다**(`error=email_taken`).

### ⚠️ GitHub Secrets 등록만으로는 서버에 안 들어간다

`deploy.yml` 이 env 를 자동 전달하지 않고 **Lightsail 배포 스펙에 한 줄씩 명시**하는 구조다.
9/9 작업로그에 이 항목이 아예 빠져 있었다 — 키만 넣고 끝냈으면 계속 `kakao:false` 였을 것이다.

```
KAKAO_REST_API_KEY / KAKAO_CLIENT_SECRET  → GitHub Secrets
KAKAO_REDIRECT_URI / OAUTH_ALLOWED_ORIGINS → 워크플로에 평문
```

- ⚠️ 카카오 키는 `os.environ.get` 으로 읽어 **없으면 항목을 뺀다.** `ADMIN_API_KEY` 처럼
  `os.environ[]` 로 쓰면 키를 넣기 전까지 **배포 전체가 죽는다**(둘은 의도가 반대다).
- Redirect URI 를 시크릿에 숨기지 않은 이유: 콘솔 등록값과 한 글자만 달라도 `KOE006` 인데
  **값이 가려지면 대조를 못 한다.** 비밀도 아니다.

### ⚠️ `gh secret set` 함정 2종 (실제로 두 번 막혔다)

1. **값을 인자로 주면 안 된다** — `gh secret set NAME value` → `accepts at most 1 arg(s)`.
   이름만 받고 값은 프롬프트/`--body`/stdin 이다.
2. **`gh` 는 현재 폴더의 레포에 넣는다** — `lighthouse-test` 에서 실행해 FE 레포로 갈 뻔했다.
   `--repo gwon6482/lighthouse-api` 를 붙이면 폴더와 무관하다.

> 두 번 다 실패했는데 에러를 흘려보내 "등록했다"고 믿고 있었다. `gh secret list` 로 확인할 것.

### OpenID Connect 는 켜지 않았다

우리는 `id_token` 을 쓰지 않는다(액세스 토큰 + `/v2/user/me`). 카카오 문서상 OIDC 는
"필요 시 설정"하는 선택 항목이고, 켜도 응답에 안 쓰는 `id_token` 이 붙을 뿐이다.
⚠️ 반대로 **쓰기 시작한 뒤 끄면 로그인이 불가능해질 수 있다**고 문서가 경고한다.

### FE (미배포)

`OAuthReturnPage.vue` 신규(`/onboarding/oauth`) + `AuthPage` 가 `providers` 조회로 버튼을 켠다.
버튼 on/off 판단을 FE 에 두지 않은 이유는 **키가 없는데 버튼만 켜지는 어긋남이 반드시 생기기** 때문.

> ⚠️ 복귀 페이지는 토큰을 읽는 **즉시** `history.replaceState` 로 주소창에서 지운다.
> 안 지우면 JWT 가 든 URL 이 히스토리·bfcache 에 남고 사용자가 그대로 복사·공유할 수 있다.
