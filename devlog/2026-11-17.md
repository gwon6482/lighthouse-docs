## 앱 핫픽스 v0.1.27 — 아이폰 사파리에서 버튼을 눌러도 다음 화면으로 안 넘어가던 문제 (운영)
- 증상(구글 신규 가입, 아이폰 사파리): '가입 완료'·'확인했어요'·'검사 시작하기'를 눌러도 아무 일이 없었다. 서버에는 가입 저장이 매번 성공으로 남았다 — 화면만 못 넘어갔다
- 원인
  - 다음 화면 파일(청크)이 없으면 CloudFront 는 index.html 을 200 으로 준다(배포가 옛 파일을 지우는데, 옛 화면이 열려 있으면 생긴다)
  - 사파리는 이를 "'text/html' is not a valid JavaScript MIME type …" 로 실패시킨다. 그런데 복구 장치(`chunkReload`)가 크롬 문구만 알았다. 크롬은 새로고침으로 넘어가서 그동안 몰랐다
  - WebKit 은 한 번 실패한 화면 파일을 같은 탭에서 새로 고쳐도 기억해, 서버에 묻지 않고 다시 실패한다(실측)
- 고침(운영 `v0.1.27`)
  - 화면 파일이 실패하면 같은 화면 안에서 그 파일을 캐시 없이 받고 한 번 더 불러온다. 그래도 안 되면 새로고침 → 앱 캐시(서비스 워커·캐시) 비우고 한 번 더 → 멈춘다. 사파리 문구도 알아본다
  - 진로 여정 시작(`/main/before`)에 로그아웃을 넣었다 — 진로계획 전에는 하단 메뉴가 없어 나갈 길이 없었다
  - 검사 첫 페이지 '이전'이 선택 화면을 새로 쌓아, 선택 화면에서 뒤로 가면 파트1 소개로 돌아가던 문제를 고쳤다
  - 배포: 새 파일을 먼저 올리고, 시작 파일(index.html·sw.js 등)은 맨 나중에 '매번 확인(no-cache)'으로 올린다. 옛 화면 파일(assets/)은 지우지 않는다(정리 방식은 따로)
- 확인
  - 가짜 API 로 가입~검사 시작 흐름 116가지를 돌렸다(이메일·구글·카카오, 뒤로·앞으로·새로고침·나갔다 다시 열기, 실패·연타, 배포 직후 옛 파일). WebKit(아이폰 13·SE)·Chromium(안드로이드) 모두 통과. 운영 v0.1.26 은 같은 시험에서 사파리 멈춤을 재현했다
  - 운영 실측: 화면 파일 이름이 로컬 빌드와 같고, index.html 은 no-cache, v0.1.26 파일은 남아 있다. 사파리 엔진에서 첫 요청만 HTML 일 때 새로고침 없이 넘어간다
- 운영 태그는 v0.1.26 + 핫픽스 6개만 담은 release 브랜치에서 냈다(main 의 '과정' 기능은 아직 스테이징). 태그 뒤 main 에 합쳤다(`b5936db`, 코드 차이 없음)
- 남은 것: 가입 흐름 개선 3가지(구글 가입 직후 뒤로 가면 '요청 만료' 문구, 이메일 가입 중 뒤로·새로고침 때 입력이 사라짐, 가입을 마친 소셜 계정이 가입 화면에 다시 닿음), 쌓이는 옛 화면 파일 정리 방식

## 앱 — 가입 흐름 다듬기 (스테이징 `d7267ea`, 다음 운영 태그에 함께)
핫픽스 v0.1.27 을 가짜 API 로 시험하다 나온 '실패는 아니지만 고칠 것' 세 가지와 검토 뒤 조정이다.

- 가입 위저드 입력을 이 탭에 1시간까지 임시 보관한다. 비밀번호와 **동의는 보관하지 않는다** — 동의는 본인이 다시 체크한다. 서버로는 보내지 않는다
  - 이메일 가입: 0단계부터 다시 시작하고 나머지 칸은 채워 둔다
  - 소셜 가입: 같은 계정이면 그 단계에서 이어간다. 동의 단계 뒤라도 동의가 비었으면 동의 단계에서 멈춘다
- 가입을 마친 계정이 가입 위저드 주소에 닿으면 앱으로 간다(소셜·이메일). 로그인된 채 이메일 가입으로 계정을 하나 더 만드는 길도 막았다

## 앱 — '이미 해 둔 것' 짝 처리 (스테이징 `cc481b8`, 다음 운영 태그에 함께)
