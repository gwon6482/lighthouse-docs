## 브랜치 정리 — `main` ↔ `dev` 양방향 머지

`dev`가 `main`보다 divergent한 채로 방치돼 있었다(dev 6커밋 / main 4커밋, 공통조상 `d912512`).
양쪽을 합쳐 **두 브랜치를 동일 상태(`4755e0c`, 트리 `90cbd59`)로** 맞췄다.

| 방향 | 방식 | 결과 |
|---|---|---|
| main → dev | `git merge main` | 머지커밋 `4755e0c`, **충돌 0건** |
| dev → main | `git merge --ff-only dev` | fast-forward |

### 충돌이 안 난 이유
`main`의 4커밋(하단나브 3탭·나브정렬·`/main` 제거·024101 더미데이터)이 건드린 파일과,
`dev`의 진로백과 스타일 분리(`.vue`의 `<style>` 블록 → `appearance/modules/encyclopedia/*.scss`)가
겹치지 않았다. 텍스트 충돌 없이 양쪽 작업이 모두 살아남는다.

### 클린 머지 ≠ 정상 — 내용 대조로 확인한 것
git이 조용히 합쳐도 한쪽 작업이 증발할 수 있어 파일 단위로 대조했다.
- main이 건드린 19개 중 16개가 main과 byte-identical, 삭제 2건(`MainPage.vue`/`.scss`) 정상 반영
- 나머지 3건은 dev도 손댄 파일 — 양쪽 다 살아있음:
  - `styles.scss`: MainPage `@use` 제거(main) + encyclopedia 14개 `@use` 추가(dev)
  - `Preparation/RecruitmentTab.vue`: `<style>` 0개(dev 리팩터 유지) + 제일기획·무신사·당근·"퍼포먼스 마케팅 리드"(main 데이터 유지)

### ⚠️ 머지 직후의 sass 에러는 코드 버그가 아니다
```
[sass] Can't find stylesheet to import.
@use './modules/survey/MainPage.scss';   ← styles.scss 4:1
```
`a82c689`가 `MainPage.scss`와 그 `@use` 줄을 **함께** 지웠으므로 디스크는 정합하다.
에러의 정체는 **머지 이전에 띄워둔 dev 서버**가 옛 `styles.scss`를 모듈 그래프에 들고 있던 것.
에러가 가리키는 4번 줄이 현재 파일에 존재하지 않는다는 게 증거다.
→ **dev 서버 재시작으로 해결.** (캐시 비우고 새로 띄운 서버에서 sass 에러 0건, `styles.scss` HTTP 200)
