## 라이브 로그는 Lightsail 컨테이너 로그에만 있다 (보존 약 3일)

파일도 pm2 도 CloudWatch 도 아니다. 로컬 `aws` CLI 로 바로 읽힌다.

```bash
aws lightsail get-container-log --region ap-northeast-2 \
  --service-name lighthouse-api --container-name app \
  --start-time <epoch> --end-time <epoch> --filter-pattern 'auth' \
  --query 'logEvents[].{t:createdAt,m:message}' --output text
```

### ⚠️ `--filter-pattern` 은 지정 구간 전체를 스캔하지 않는다

한 페이지(100건)만큼 훑고 멈춘다. 그래서 **넓은 창이 더 적게 잡히는 모순**이 나온다.

```
48h 창 → auth=1
96h 창 → auth=0      ← 더 옛날부터 스캔하다 100건 상한에 먼저 걸린다
```

처음에 24h 창에서 `auth=0` 을 보고 "프로덕션에 아무 요청도 없었다"고 **틀린 결론**을 냈다.
로그의 99%가 헬스체크(ELB 4대 × 10초 = 분당 24건)라 상한을 금방 채운다.

해결: **창을 4분 단위로 쪼개서** 돈다(4분 ≈ 100건).

```bash
NOW=$(date -u +%s)
for i in 0 4 8 12 16 20; do E=$((NOW-i*60)); S=$((E-240));
  aws lightsail get-container-log ... --start-time $S --end-time $E \
    --filter-pattern 'auth' --query 'length(logEvents)' --output text; done
```

> ⚠️ morgan 이 쿼리스트링을 통째로 찍어서 OAuth `code=` 와 `state=` 가 평문으로 남는다.
> 둘 다 단명(코드 1회용 / state 10분)이라 즉각적 위험은 낮지만, 로그를 붙여넣을 때는 잘라낼 것.
> `state` 는 그냥 base64 라 디코드하면 `returnTo` 가 바로 보인다 — 어느 도메인으로 돌아갔는지
> 확정하는 가장 빠른 방법이다.

같이 실어야 하는데, 그러면 API 배포가 하나 더 붙는다. 제공자가 늘어도 다시 어긋나지 않는

## 출시를 일부러 멈춰 세웠다 — 구글 동의 화면이 아직 '테스트 중'

구글은 **API 는 라이브**(`providers.google=true`)인데 **FE 가 프로덕션에 안 나가 있다.**
프로덕션(v0.1.10)의 `AuthPage` 는 구글 버튼이 `comingSoon('구글')` 하드코딩이다.

여기서 그냥 태그하면 이렇게 된다:

```
구글 버튼이 프로덕션에 보인다
  → 사용자가 누른다
  → 동의 화면이 '테스트 중' 이라 등록된 테스트 사용자 외에는 access_denied
  → 우리 쪽 error=cancelled → "로그인을 취소했어요" (취소한 적 없는데)
```

**보이는데 안 되는 기능**은 '준비 중' alert 보다 나쁘다. 그래서 태그를 미뤘다.

> ⚠️ 구글의 `access_denied` 는 우리 콜백에서 `req.query.error` 로 들어와 **전부 `cancelled`**
> 로 뭉개진다. '테스트 사용자가 아님'과 '사용자가 취소함'이 화면에서 구분되지 않는다.
> 동의 화면을 게시하면 실질적으로 취소만 남으므로 지금은 두지만, 알아둘 것.
