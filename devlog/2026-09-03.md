### ⚠️ 건너가는 장이 화면을 가로지르면 안 된다

덱은 슬롯 3개(`is-front` / `is-next` / `is-prev`)를 한 칸씩 돌린다. 그러면 한 주기에
한 장은 반드시 `is-prev → is-next`로 **건너가야** 한다.

처음엔 그냥 가로질러 미끄러지게 뒀는데, 전환 내내 폰 3대가 흩어져 **"한 화면만 앞"이
무너졌다**(특히 왼쪽에 두 대가 겹쳐 보임). 슬로모션 프레임을 떠서 확인했다.

→ 가로지르지 않는다. `@keyframes deck-wrap`으로 **제자리에서 사라졌다 반대편에서 나타난다.**
그동안 `z-index: 0`이라 물러나는 앞장이 덮어줘서 사라지는 순간이 눈에 안 띈다.
결과적으로 눈에 보이는 이동은 2장뿐이다.

> `@keyframes`는 중첩할 수 없어 믹스인 안에 못 둔다. `_mixins.scss`는 `additionalData`로
> 파일마다 주입되므로 거기 두면 복제된다 → **`main.scss`에 한 번만** 뒀다.
> Nuxt가 전역 CSS를 HTML에 인라인하므로 빌드 산출물에서는 `_nuxt/*.css`가 아니라
> 각 페이지 HTML 안에 들어간다. 거기만 grep하면 없는 줄 안다.

### ⚠️ 목업 실측 상수가 틀려 있었다

8/31 부채꼴이 쓰던 값(`padL 0.093` / `bodyW 0.726` / `bodyH 0.855`)은 **알파 임계값을 낮게
잡아 드롭섀도까지 본체로 센 값**이었다. 캔버스 알파 255로 재측정한 실제 값:

```
목업 webp 1119×1800 · 본체 x 205~912 / y 175~1626 → 폭의 63.27%
여백은 좌우·상하 모두 대칭이다 (좌우 205·206 / 상하 175·173)
```

**상수를 두 벌로 나눴다.** 덱은 실측값(`$mock-*`), 부채꼴은 옛 값(`$fan-*`)을 그대로 쓴다 —
부채꼴에 실측값을 넣으면 폰이 15% 커지고 무리가 왼쪽으로 6% 옮겨가 **이미 배포된
태블릿·데스크탑 화면이 바뀐다.** 부채꼴을 손볼 일이 생기면 그때 갈아탈 것.

### 목업 해상도 900 → 1800

덱에서 표시 크기가 커지면서(본체 309 → 403px) 원본 559×900(본체 353px)을 **확대해서**
쓰게 돼 눈에 띄게 뭉갰다. `sips -Z 1800` + `cwebp -q 78`로 재인코딩(본체 708px).

- 원본↔배포본 대응은 **옛 파이프라인 재생성본의 SHA1 대조**로 확정했다(30장 중 15장 정확히 일치)
- `loading="lazy"` + `decoding="async"` — 전부 첫 화면 아래라 초기 로딩엔 영향 없음
- 목업 합계 708KB → **2.8MB**, 빌드 산출물 5.6 → 7.9MB
- 후속: `srcset`(559w/1119w) 도입 여지. 태블릿 이상은 부채꼴이라 작게 표시하는데 큰 파일을 받는다

### 진입 시 항상 맨 위로

`plugins/scrollTop.client.ts` 신설. `history.scrollRestoration`이 기본값(`auto`)이면
새로고침 전 위치가 복원되는데, 이 랜딩은 진입 직후 **4초짜리 스플래시가 덮으므로**
걷히고 나면 페이지 중간에 서 있게 된다. `manual`로 두고 진입·`app:mounted`·`load`에 맨 위로.

라우트 간 이동(vue-router `scrollBehavior`)과 bfcache 복원은 일부러 안 건드렸다.

### 폰 실기 확인 — `npm run dev:host`

> ⚠️ `--host`를 **값 없이** 주면 Nuxt CLI 3.20.1이 boolean `true`로 넘겨서
> `The "hostname" argument must be of type string. Received type boolean (true)`로 죽는다.

`#app-manifest` Pre-transform 에러는 `generate` 산출물 기준으로 남은 캐시 잔재다(치명적 아님).
`rm -rf .nuxt .nitro .cache node_modules/.vite node_modules/.cache`로 사라진다.

### ⚠️ `lighthouse-landing`에는 원래 `dev` 브랜치가 없었다

`dev`는 **`lighthouse-test`(FE 모노레포)** 쪽 관례다. 랜딩은 `main` 하나로만 굴러왔고
`main` push가 곧 프로덕션 배포다(스테이징 없음).

이번에 랜딩에도 `dev`를 만들어 `dev`·`main`을 같은 커밋으로 맞췄다.

> `LighthouseProject/`는 **모노레포가 아니다** — git 레포도 아닌 그냥 폴더이고,
> 안에 독립 레포 4개가 나란히 있을 뿐이다. CLAUDE.md의 "FE 모노레포"는
> `lighthouse-test` **한 레포 안**의 pnpm workspaces를 가리키는 말이다.
