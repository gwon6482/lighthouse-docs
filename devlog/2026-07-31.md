# 개발일지 2026-07-31

## 관리자/서비스 API 보안 강화 (인증·IDOR·레이트리밋) + 배포

API 인증 감사 결과, `/api/admin`뿐 아니라 **직업·참조데이터 쓰기 엔드포인트가 공개 라우터에 무인증 노출**되어 있어(누구나 직업/참조데이터 생성·수정·삭제 가능) 전면 조치.

### 조치 (lighthouse-api)
- **adminAuth 미들웨어**: `x-admin-key`를 SHA-256 후 `timingSafeEqual` 비교. `ADMIN_API_KEY` 미설정 시 **503 fail-closed**(키 없이 열리는 사고 방지).
- **보호 대상**: `/api/admin/*`, `job POST/PUT/DELETE`, `reference POST/PUT/DELETE`(survey-elements·career-attributes), `survey POST /statistics/update`·`GET /result/list`. GET 조회(직업 목록/검색/후기, 참조 조회, 통계)는 유저앱용이라 공개 유지.
- **검사결과 IDOR**: `GET /analysis/:survey_id`·`/t1-result/:survey_id`에 `authenticate` + 소유권 검사(`ensureSurveyOwnership`: `User.surveyResults`로 판정, 타인 403, 미소유는 claim-on-read로 자가치유해 FE link 실패에도 결과화면 안 깨짐). `POST /report`는 FE 미사용·Admin 전용이라 `adminAuth`.
- **레이트리밋**: `express-rate-limit` v8 + `app.set('trust proxy', 1)`(Lightsail LB 1홉). `/login`(실패 10회/10분, skipSuccessfulRequests로 CGNAT 오탐↓), `/check-email`(30회/10분).

### 조치 (lighthouse-admin)
- **서버 프록시 도입**: `app/api/proxy/[...path]/route.ts` — NextAuth 세션 검증 후 서버 전용 `ADMIN_API_KEY`를 `x-admin-key`로 주입해 API로 포워딩(키 브라우저 미노출). axios baseURL `/api/proxy`, dormant rewrite 제거.

### 배포 (Admin→API 순서)
- env: `ADMIN_API_KEY`를 GitHub Secret(lighthouse-api, **Repository secret**)·Vercel(lighthouse-admin) 양쪽 동일값. GitHub Actions `deploy.yml`이 Lightsail 컨테이너 env로 주입.
- **삽질 기록**: 최초 배포 시 GitHub Secret이 실제로는 없어(없는 시크릿 참조가 빈 문자열이 됨) 컨테이너가 `ADMIN_API_KEY=""` → 전 관리자 API 503. 원인은 키를 lighthouse-admin 레포의 *환경* 시크릿에 잘못 등록. lighthouse-api **레포 시크릿**으로 재설정(CLI) 후 재배포로 해결.
- 라이브 검증: 무키 → 401, 정답키 → 200, admin.lighthouse.career 로그인→문항 조회 200(프록시 경유), 유저앱 공개 엔드포인트 정상.

### 남은 것
- **⚠️ 관리자 로그인 비밀번호가 약함(`changeme`)** → 프로덕션 `ADMIN_PASSWORD` 로테이션 권장.
- CORS 오리진 화이트리스트(모바일 오리진 확정 후), 관리자 role 세분화, JWT_SECRET 로테이션은 후속.
