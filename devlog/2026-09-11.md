## 카카오 가입자도 이메일 가입과 같은 위저드를 거치게

카카오 로그인이 **가입 위저드를 통째로 건너뛰고** 곧장 `/main/before` 로 갔다.
콜백은 계정만 만들고 끝나서 **나이·성별·진로답변 Q1~Q3 가 전부 빈 채로 남았다** —
9/9 에 '버려지던 답을 남기게' 만든 `User.onboarding` 이 소셜 경로에서 다시 비어버린 셈이다.

```
카카오 로그인 → 콜백(계정 생성) → /onboarding/oauth
  → onboarding 없음? → 가입 위저드 (계정 단계만 생략, 이름 프리필)
  → /onboarding/intro → welcome → /main/before   ← 이메일 가입과 동일
```

| | 자동 | 직접 입력 |
|---|---|---|
| 카카오 | 이메일(계정에 이미 있음), 이름(닉네임) | 나이·성별·Q1·Q2·Q3 |

### `POST /api/auth/complete-profile` 신규

소셜은 **콜백에서 계정이 이미 만들어진다.** 그래서 위저드 끝에서 `register` 를 부르면 409 다.
`register` 가 한 번에 하던 일을 '계정 생성(콜백)' + '나머지 채우기(여기)' 로 나눴다.

- 검증은 `register` 와 **같은 `buildOnboarding`** 을 재사용한다(두 벌로 두면 반드시 어긋난다)
- 보내온 필드만 덮어쓴다 — 위저드를 두 번 돌아도 이미 채운 값이 날아가지 않게

### ⚠️ "local 이 없으면 소셜" 로 판정하면 옛 계정이 위저드에 갇힌다

위저드를 중간에 이탈한 소셜 계정을 다시 위저드로 돌려보내는 가드를 `app.ts` 에 넣으면서
처음엔 `!authProviders.some(p => p.provider === 'local')` 로 썼다. 그러면 `authProviders` 가
비어 있는(기본값 `[]`) 옛 계정까지 소셜로 잡힌다. **2026-09-09 이전 이메일 가입자는
`onboarding` 도 없어서 실제로 갇힌다.** → **소셜 항목이 있는가**로 판정하도록 뒤집었다.

### ⚠️ 서비스워커가 옛 번들을 내준다 — 코드 문제로 오인했다

배포 직후 `/onboarding/signup?social=1` 이 step 0(계정 만들기)으로 떠서 social 모드가 안 먹는 줄
알았다. 실제로는 브라우저가 **이전 방문 때 설치된 PWA 서비스워커 캐시**로 구버전 번들
(`index-DHK99b4Z.js`)을 쓰고 있었다. 서버가 주는 청크에는 `query.social==="1"` 이 정확히 있었다.

```
navigator.serviceWorker.controller → sw.js (controlled)
로드된 스크립트 index-DHK99b4Z.js   (서버 최신 index-Cdfnl4-3.js)
```

`registerType: 'autoUpdate'` 라 결국 갱신되지만 **그 방문에는 옛 화면이 보인다.**

> 배포 직후 확인은 **curl 로 받은 청크 내용**과 **브라우저가 실제 로드한 번들**을 따로 볼 것.
> 둘이 다를 수 있다. 브라우저만 보고 '반영 안 됨'이라 판단하지 말 것.
