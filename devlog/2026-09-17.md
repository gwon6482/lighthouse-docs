### 이메일 가입 vs 카카오 가입 — 무엇이 어디에 저장되나

둘 다 `user_data.users` 의 같은 `User` 문서다. 갈리는 것은 **누가 채우느냐와 계정이 언제 생기느냐**다.

| User 필드 | 이메일 (`register` 1회) | 카카오 (콜백 + `complete-profile`) |
|---|---|---|
| `email` | 입력값 | 동의 시에만. 미동의면 **없음**(sparse unique) |
| `passwordHash` | bcrypt(10) | **없음** → 이메일 로그인 영구 불가 |
| `authProviders` | `[{local, providerId: 이메일}]` | `[{kakao, providerId: 회원번호}]` |
| `name` | 위저드 입력 | 콜백이 닉네임으로 선채움 → 위저드에서 수정 |
| `age`·`gender` | 위저드 입력 | 콜백엔 없음 → `complete-profile` 에서만 |
| `onboarding` | `register` 본문에 동봉 | `complete-profile` 에서만 |
| 계정 생성 시점 | 위저드 **끝** | 위저드 **전**(콜백) |

마지막 줄이 구조적 차이의 뿌리다. 카카오는 계정이 먼저 생기므로 위저드 도중 이탈하면
**나이·성별·Q1~Q3 가 빈 계정이 DB 에 남는다.**

## 카카오만 lastLoginAt 이 안 찍히고 있었다

위 비교표를 만들다 발견했다. `login` 은 `lastLoginAt` 을 갱신하는데 `kakaoCallback` 은
기존 유저를 그대로 return 해서 **카카오 유저만 마지막 접속 집계에서 통째로 빠진다.**

### ⚠️ 여기서 `save()` 를 쓰면 로그인이 죽을 수 있다

`login` 이 `user.save()` 를 쓰니 따라 쓰고 싶어지지만, `save()` 는 **문서 전체 검증을 다시 돌린다.**
옛 계정에 스키마와 어긋난 값이 하나라도 있으면 그 사용자는 **로그인 자체가 실패한다.**
필드 하나 찍자고 낼 대가가 아니다 → `updateOne({$set:{lastLoginAt}})`.

```js
const now = new Date();
await User.updateOne({ _id: existing._id }, { $set: { lastLoginAt: now } });
existing.lastLoginAt = now;   // 호출부가 방금 쓴 값을 보게
```

신규 가입 경로(`User.create`)에도 `lastLoginAt` 을 넣어 두 경로를 맞췄다.

## 나이·성별 검증이 두 벌로 갈라져 있었다

`completeProfile` 에는 1~120 검증이 있는데 `register` 에는 **없었다.** 그래서 같은 잘못된 값이
경로에 따라 400 이 되기도 하고 Mongoose ValidationError → **500** 이 되기도 했다.
`buildOnboarding` 을 공유한 것과 같은 방식으로 `validateProfile` 하나를 둘이 쓰게 했다.

> 9/11 에 "검증을 두 벌로 두면 반드시 어긋난다"고 적어놓고 **나이·성별은 두 벌로 두고 있었다.**
> 원칙을 적은 것과 지킨 것은 다르다.

### ⚠️ 빈 문자열을 통과시키자 다른 곳이 깨졌다

`age: ''` 를 '보내지 않음'으로 보고 통과시키면 `completeProfile` 의 대입부에서
`Number('') === 0` 이 되어 스키마 `min:1` 에 걸린다. 대입부에도 `age !== ''` 를 넣었다.
**검증을 느슨하게 한 대가가 다른 줄에서 나온다.**
